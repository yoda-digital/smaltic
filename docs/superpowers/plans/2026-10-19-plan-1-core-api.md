# Smaltic Plan 1: Core server and read/write APIs (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless server that the official Prismic SDKs work against unchanged. Models are pushed with `@prismicio/custom-types-client`, content is imported with the `@prismicio/client` WriteClient, and content is read back with `@prismicio/client`, including filters, orderings, links, routes, releases and preview refs.

**Architecture:** Fastify 5 server (`apps/server`) on PostgreSQL 16 (JSONB content, immutable versions, ref sequence). A shared package `@smaltic/model` holds model schemas and the content normalize/render pipeline. The Content API compiles Prismic filters to SQL over the set of versions visible at a ref.

**Tech Stack:** Node 22, TypeScript 5 (strict, ESM, NodeNext), pnpm 10 workspaces, Fastify 5, `postgres` 3 (porsager), zod 3, vitest 2, `@node-rs/argon2`, official `@prismicio/client` 7.22.x and `@prismicio/custom-types-client` 2.x as **test** dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-smaltic-design.md`. Contracts: `docs/research/api-contracts.md` (cited **C§**), `docs/research/rea/01-apis-and-delivery.md` (**R1§**), `rea/02-content-modeling.md` (**R2§**), `rea/04-sdks-and-frameworks.md` (**R4§**). Live shapes: `docs/research/evidence/`. Implementers must read the cited sections. They are the spec for wire formats, and this plan does not repeat them.

## Global Constraints

- Product name in code, UI and logs is **Smaltic**. Never use Prismic logos or branding; "Prismic-compatible" may appear only as a description.
- Wire compatibility beats docs. When docs and live evidence disagree, follow the evidence (R1 discrepancy register).
- Repository names match `/^[a-zA-Z0-9][-a-zA-Z0-9]{2,}[a-zA-Z0-9]$/` (C§0.1).
- Timestamps in API output use the format `YYYY-MM-DDTHH:mm:ss+0000` (exactly 24 chars, UTC).
- Document and ref ids are 16 chars from `[A-Za-z0-9_-]`, generated by `newId()` (Task 3).
- `languages[0]` in `/api/v2` is always the master locale (C§0.10).
- Every error body and message the SDK parses is reproduced verbatim, including the ` Master ref is: <ref>` suffix (C§0.6) and `Retry-After` on every 429 (C§0.7).
- Stored versions are immutable: no `UPDATE` on `document_versions.content` anywhere in the code.
- All absolute URLs the server emits are built by `publicUrl(req, path)` (Task 3), never hard-coded.
- Server env: `DATABASE_URL`, `SMALTIC_PUBLIC_URL` (fallback when headers are absent), `SMALTIC_BASE_DOMAIN` (optional, enables subdomain routing), `SMALTIC_SECRET` (HMAC key), `SMALTIC_DATA_DIR` (blobs, default `./data`), `SMALTIC_TRUST_PROXY` (default `true`).
- Tests run against the Postgres from `docker-compose.yml` (`postgres://prismic:prismic@localhost:5433/prismic`). Each test file gets its own database, created by `createTestDb()` (Task 1).

## Review Focus

1. A `ref` that is the toolbar's URL-encoded JSON cookie (`{"<host>":{"preview":"<token>"}}` with `%22`/`%2C`) must resolve to that preview. Test: Task 12 `accepts toolbar JSON cookie as ref`.
2. Content stored under an old model, with a field since removed or retyped, must render without a 500. Removed fields are hidden; retyped fields render as empty. Test: Task 5 `renders content after model change`.
3. Two concurrent publishes must yield two distinct, monotonically ordered master refs with no lost version. Test: Task 6 `concurrent publishes are serialized`.
4. When the server sits behind a reverse proxy on path-prefix addressing (`/r/<repo>`), the emitted `next_page`, `href` and `forms.*.action` must keep the prefix, scheme and host from `X-Forwarded-*`. Test: Task 10 `emits proxied absolute URLs`.
5. Unicode in UIDs, tags and fulltext (`"café"`, Cyrillic, emoji) must round-trip, and fulltext must match accent-insensitively. Test: Task 9 `fulltext unicode and accents`.
6. `page` beyond the last page must return 200 with `results: []` and correct totals, never an error. Test: Task 10 `page past the end`.
